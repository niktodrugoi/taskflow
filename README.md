# TaskFlow

Веб-приложение «Список задач» на чистом HTML, CSS и JavaScript. Задачи хранятся в браузере и сохраняются между перезагрузками страницы.

**Демо:** после публикации на GitHub Pages адрес будет `https://<ваш-логин>.github.io/<название-репозитория>/` (ссылку нужно подставить вручную).

## Возможности

- Добавление задач кнопкой или клавишей Enter; пустые задачи отклоняются, пробелы по краям удаляются.
- Новые задачи появляются в начале списка, у каждой уникальный ID.
- Отметка выполнения чекбоксом и возврат в активное состояние.
- Удаление отдельной задачи.
- Счётчики: всего, выполнено, осталось.
- Фильтры «Все», «Активные», «Выполненные» с подсветкой текущего.
- Отдельные сообщения для пустого списка и пустого фильтра.
- «Очистить выполненные» с диалогом подтверждения.
- Адаптивная вёрстка, управление с клавиатуры, видимый фокус.

## Технологии

HTML5, CSS3, JavaScript (ES6+), localStorage. Без фреймворков и зависимостей.

## Структура

```
taskflow/
├── index.html
├── css/style.css
├── js/app.js
├── .github/workflows/pages.yml
├── README.md
└── .gitignore
```

В `app.js` код разделён на модули: `Storage` (localStorage), `Tasks` (операции над задачами), функции отображения (`render`, `createTaskItem`) и обработчики событий.

## Локальный запуск

Сборка не нужна: откройте `index.html` в браузере. Либо запустите локальный сервер:

```bash
python -m http.server 8000
```

и откройте http://localhost:8000.

## Хранение данных

Задачи сохраняются в `localStorage` под ключом `taskflow.tasks.v1` в виде JSON-массива `{ id, text, completed }`. При загрузке данные проверяются: если значение отсутствует, повреждено или имеет неверный формат, приложение стартует с пустым списком и не падает с ошибкой. Данные привязаны к браузеру и домену.

## Публикация на GitHub Pages

В репозитории есть workflow `.github/workflows/pages.yml`. Чтобы он заработал: в настройках репозитория выберите **Settings → Pages → Source: GitHub Actions**, затем отправьте код в ветку `main`.
